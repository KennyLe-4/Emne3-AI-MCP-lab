AI-SOC-agent med MCP

Bygg en MCP-server som gir en AI-agent lesetilgang til Wazuh, og la den hjelpe deg å analysere angrepene du selv kjører.

Etikk og rammer: alt kjøres kun i ditt eget, isolerte lab-miljø. Agenten får bare lesetilgang til Wazuh. Den kan ikke endre, slette eller svare på angrep. Gi aldri en AI-agent mer tilgang enn oppgaven krever. Den regelen gjelder like mye i en ekte jobb som her i laben.

Hva du bygger

Du har allerede en SOC fra forrige lab: Wazuh på Kali, med victim som aktiv agent. Nå setter du en AI-agent oppå. En liten MCP-server (ett Python-script) oversetter Wazuh sitt API til «verktøy» en agent kan kalle. Da kan du spørre SOC-en på vanlig norsk, for eksempel «hva skjedde mot victim siste time?», i stedet for å klikke deg gjennom dashbordet.

Claude
agenten: resonnerer og kaller verktøy
→
MCP-server
wazuh_mcp.py, 6 verktøy
→
Wazuh
API 55000 + indexer 9200

MCP (Model Context Protocol) er en standard måte å koble en AI-agent til verktøy og data. Flyten er enkel: agenten spør, serveren henter fra Wazuh, og agenten tolker svaret. Det eneste som sendes til Claude er det agenten faktisk spør om, ikke hele Wazuh. Vi kommer tilbake til hvorfor det er viktig i oppgavene.

Mål for laben

  • K6 Forstå deteksjon og hvordan logger, hendelser og alarmer blir til analyserbar kontekst.
  • K9 Se samspillet mellom offensivt (angrepet du kjører) og defensivt (det agenten leser i Wazuh).
  • K11 Kjenne SOC-analytikerrollen og hvordan AI-verktøy brukes i den.
  • T.13.5 Vurdere begrensningene i automatisering: hva agenten gjør godt, og hvor mennesket må inn.

Forutsetninger Fra Kali

Før du starter må forrige lab være oppe. Sjekk raskt:

  • Wazuh-dashbordet åpner på https://localhost i Kali sin Firefox.
  • Victim viser Active under Agents i dashbordet.
  • Du har en (gratis) Claude-konto til innlogging.
Bekreft at de to Wazuh-API-ene svarer (401 = oppe, bare uten token):
curl -k https://127.0.0.1:55000
curl -k https://127.0.0.1:9200

Steg 1: Hent legitimasjonen Fra Kali

Wazuh-API-et krever brukernavn og passord. I Docker-oppsettet ligger de i din egen docker-compose.yml. Du henter dem derfra, så du slipper å få dem tilsendt. Dette eksporterer dem rett inn i miljøet (passordet vises aldri på skjermen):

cd /opt/wazuh-docker/single-node
export WAZUH_API_USER='wazuh-wui'
export WAZUH_API_PASS=$(grep -m1 API_PASSWORD docker-compose.yml | cut -d= -f2)
export WAZUH_INDEXER_USER='admin'
export WAZUH_INDEXER_PASS=$(grep -m1 INDEXER_PASSWORD docker-compose.yml | cut -d= -f2)
Merk deg dette: oppsettet bruker fortsatt standardpassordene som fulgte med Wazuh-imaget. I lab er det greit, men hos en kunde er dette nettopp den feilen en SOC-analytiker skal fange opp. Default-passord som aldri ble endret er et reelt funn.

Steg 2: Lag MCP-serveren Fra Kali

Klon repoet (det inneholder wazuh_mcp.py og .mcp.json), lag et virtuelt Python-miljø, og installer de to pakkene serveren trenger.

cd ~
git clone https://github.com/KennyLe-4/Emne3-AI-MCP-lab.git
cd Emne3-AI-MCP-lab
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
Åpne gjerne wazuh_mcp.py og les den. Det er under 200 linjer, og hvert @mcp.tool() er ett verktøy agenten kan kalle. Dette er MCP-serveren. Ingen magi der.

Steg 3: Selvtest Fra Kali

Før du kobler på AI: sjekk at serveren når Wazuh. Kjør den i selvtest-modus (bruker passordene du eksporterte i Steg 1, så de må være satt i samme terminal).

python wazuh_mcp.py --selftest

Du skal se "ok": true for både manager og indexer, en liste over agenter (deriblant emne3-victim), og hvilke regler som har fyrt mest:

Kali — selvtest
(.venv) kali@kali:~/Emne3-AI-MCP-lab$ python wazuh_mcp.py --selftest
{
  "manager": { "ok": true, "version": "4.14.8" },
  "indexer": { "ok": true, "version": "7.10.2" }
}
[
  { "id": "001", "status": "active", "name": "emne3-victim", "ip": "192.168.64.9" }
]
Feiler den? Connection refused = Wazuh er ikke oppe (sjekk Docker). 401 i feilen = feil passord (gjorde du Steg 1 i samme terminal?). Fiks det før du går videre. Er ikke selvtesten grønn, hjelper det ikke å koble på Claude.

Lag en gratis Claude-konto

Du trenger en Claude-konto for å logge inn i neste steg. Gratis-kontoen holder fint til denne laben, og du trenger ikke oppgi betalingskort. Dette gjør du bare én gang:

  1. Gå til claude.ai i nettleseren.
  2. Klikk Sign up, og registrer deg med e-post eller en Google-konto.
  3. Bekreft e-posten hvis du blir bedt om det.
Selve innloggingen skjer i Steg 4. Når du starter claude for første gang, åpner den nettleseren og ber deg logge inn med denne kontoen. Du logger inn én gang, så husker den deg etterpå.
Gratis-kontoen har en daglig meldingsgrense. Hvert spørsmål til agenten teller mot den, og agenten gjør gjerne flere verktøy-kall per spørsmål, så grensen nås raskere enn ved vanlig prat. Jobb to og to og hold spørsmålene korte, så rekker dere gjennom hele laben på én økt.

Steg 4: Installer Claude Code og koble på Fra Kali

Claude Code er terminal-versjonen av Claude, og den kan bruke MCP-servere. Installer den, logg inn, og registrer serveren din.

Installer (hopp over om claude --version allerede svarer)
curl -fsSL https://claude.ai/install.sh | bash
export PATH="$HOME/.local/bin:$PATH"
claude --version
Registrer Wazuh-serveren (kjør fra repo-mappa, i samme terminal der passordene er satt)
claude mcp add wazuh -- $(pwd)/.venv/bin/python $(pwd)/wazuh_mcp.py
claude mcp add fanger miljøvariablene fra terminalen den kjøres i. Derfor må passordene fra Steg 1 fortsatt være eksportert her. Byttet du terminal underveis, kjør Steg 1 på nytt først.
Start Claude
claude

Første gang åpner den nettleseren for innlogging, så godkjenn med Claude-kontoen din. Den spør også om du stoler på MCP-serveren i prosjektet; svar ja.

Steg 5: Første spørsmål Fra Kali

Inne i Claude, sjekk først at verktøyene er lastet:

/mcp

Du skal se wazuh med seks verktøy. Still så det første ekte spørsmålet. Skriv det som en vanlig melding:

Kjør wazuh_status, og oppsummer hva som har skjedd mot emne3-victim
siste 60 minutter. Hvilke regler lager mest stoy?
Legg merke til hva som skjer: agenten velger selv hvilke verktøy den kaller og i hvilken rekkefølge, og tolker svaret. Du ba ikke om et bestemt API-kall, du beskrev et mål. Et script hadde gjort nøyaktig det du skrev; agenten finner ut stegene selv.

Steg 6: Angrip, så la agenten oppdage Fra Kali

Nå ser du hele sløyfa. Åpne en ny terminal på Kali (ikke i Claude-økta) og kjør et angrep mot victim. Bytt inn victim sin IP.

VICTIM=192.168.x.x
hydra -l labadmin -P /usr/share/wordlists/rockyou.txt ssh://$VICTIM -t 4 -f

Vent et minutt, gå tilbake til Claude-økta, og spør:

Det kom nettopp SSH-trafikk mot emne3-victim. Finn brute force-forsok,
gi meg kilde-IP, antall forsok, hvilken Wazuh-regel som fyrte og MITRE-teknikken.
Er dette et ekte funn eller stoy?
Dette er T.15 i praksis: fra angrep til forsvar. Samme hendelse, sett fra to sider: verktøyet du kjørte, og analytikeren (agenten) som leser sporene i Wazuh.

Oppgaver

Nå er oppsettet ferdig. Resten er analyse. Jobb deg gjennom oppgavene. Prøv selv først; fasit ligger nederst, men den er mye mindre verdt hvis du åpner den for tidlig.

Oppgave 1: Still de fem analytiker-spørsmålene

Få agenten til å hjelpe deg svare på disse, og noter svarene. Vær kildekritisk, og sjekk at det agenten påstår faktisk står i dataene.

  1. Hvilke kilde-IP-er står bak flest alarmer, og hva forsøkte de?
  2. Hvilke tre regler fyrer mest? Hvor mange av dem er reell trussel vs. støy?
  3. Nådde SSH brute force-forsøket ditt helt frem til en vellykket innlogging, eller stoppet det på forsøk?
  4. Finnes det alarmer agenten ikke klarer å forklare godt? Hvorfor?
  5. Hvis du var SOC Tier 1: hvilke alarmer ville du eskalert, og hvilke ville du avfeid?

Oppgave 2: Utfordring, gi agenten et nytt verktøy Fra Kali

Ingen oppskrift her. Åpne wazuh_mcp.py, se hvordan et @mcp.tool() er bygget, og legg til ett nytt verktøy selv, for eksempel get_failed_logins(minutes) som henter mislykkede innlogginger, eller alerts_for_ip(ip) som viser alt fra én IP. Start Claude på nytt, og be agenten bruke det nye verktøyet.

Mål: forstå at du selv bestemmer hva agenten kan. Den har ikke magisk tilgang, bare de verktøyene du ga den.

Oppgave 3: Refleksjon (T.13.5)

Skriv kort (3 til 5 setninger per punkt):

  • Hva gjorde agenten raskere eller bedre enn å klikke i dashbordet selv?
  • Hvor tok den feil, overdrev, eller «fant på» noe som ikke stemte med dataene?
  • Hvorfor ga vi den bare lesetilgang? Hva kunne gått galt med skrive-/responstilgang?
  • Ville du stolt på denne agenten alene i en ekte SOC? Hva måtte eventuelt være på plass først?
Fasit og veilederkommentarer (åpne etter at du har prøvd selv)

Oppgave 1: Svarene avhenger av hva du kjørte, men pek studentene mot: brute force-IP = Kali sin lab-IP (regel 5710/5712-serien, MITRE T1110). Mest støy i et friskt lab er typisk rootcheck (regel 510) og eventuelle Suricata ET INFO-alarmer, som er lavt nivå og ikke trussel. «Ekte funn» = brute force og eventuelle web/command-injection-treff; «støy» = rootcheck, P2P-info, Wazuh start/stop-meldinger.

Punkt 3 (viktig): hydra med rockyou treffer ikke riktig passord (labadmin2026 ligger neppe tidlig i lista), så Wazuh ser mange authentication_failed men ingen authentication_success. Et godt svar skiller forsøk fra vellykket innbrudd. Det er kjernen i å lese en brute force riktig.

Punkt 4: agenten sliter med alarmer der konteksten ikke finnes i Wazuh (f.eks. execve/prosess-oppførsel som bare ligger i auditd, ikke ingestet). Det er et reelt poeng om synlighetsgrenser (T.10.6): agenten kan bare se det datakilden faktisk sender.

Oppgave 2: et korrekt nytt tool følger mønsteret: @mcp.tool(), en funksjon med typede argumenter og docstring (agenten leser docstringen for å forstå når verktøyet skal brukes), som kaller _idx_search(...) eller _api_get(...) og returnerer JSON. Poenget er at de ser koblingen mellom hvilke verktøy serveren har og hva agenten kan gjøre, ikke at koden er feilfri.

Oppgave 3: det er ikke noe fasitsvar, men gode refleksjoner nevner: hallusinasjon/overtolkning, at agenten er like god som datakilden og regelkvaliteten (T.9.5), minste privilegium (derfor lesetilgang), og at mennesket må validere før eskalering/respons. «Ville du stolt på den alene?» Forventet svar er nei: ikke uten menneske-i-loop, logging av tool-kall og begrensede rettigheter.

Hvis noe krangler

  • claude: command not found etter installasjon → export PATH="$HOME/.local/bin:$PATH", evt. åpne nytt terminalvindu.
  • /mcp viser ingen wazuh-server → du registrerte den i en annen mappe/terminal. Kjør claude mcp add på nytt fra repo-mappa, med passordene satt.
  • Agenten svarer at tool-kall feiler med 401 → passordene var ikke eksportert da du kjørte claude mcp add. Sett dem (Steg 1) og registrer på nytt.
  • Tomt svar / ingen alarmer → kjør et angrep (Steg 6) først, så er det noe å finne.
